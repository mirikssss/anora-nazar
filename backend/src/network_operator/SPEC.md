# Сеть кредиторов: контракт network-contract-1

Схемы — `shared/contracts/network.py`. Источник по продукту — Блок 2 «Сеть кредиторов», Блок 3 (признаки сети), Блок 4 (исходы дела → в сеть), «Решения по ревью ядра» (пороговый OPRF — цель, в демо один ключ на тип).

Гипотеза И4: межбанковские совпадения находят схемы, которых не видит один банк, и участники не обмениваются исходными идентификаторами.

## Участники

| Кто | Что делает |
| --- | --- |
| Кредитор A — узел Anora Nazar | токенизирует идентификаторы заявки, шлёт события активности и результаты закрытых дел, спрашивает счётчики, получает уведомления о новых совпадениях |
| Кредиторы Б и В — генераторы в `bank-sim` | тот же клиент OPRF: события активности и результаты своих дел |
| Оператор сети — `network-operator` | применяет ключ OPRF, хранит токены и события, считает счётчики, рассылает уведомления, ограничивает запросы, ведёт журнал запросов |

Банк знает только свои значения и полученные токены. Оператор видит только токены, ослеплённые элементы и счётчики.

## Токены

1. **Типы:** `pinfl` (14 цифр), `phone` (`998` и 9 цифр), `device` (строка без пробелов по краям, нижний регистр, до 128 символов), `card` (16 цифр), `supplier_inn` (9 цифр). Нормализация — `shared/network/normalize.py`, одна для всех кредиторов. Неверный формат — ошибка у кредитора, в сеть ничего не уходит.
2. **OPRF** — RFC 9497, режим OPRF (0x00), набор ristretto255-SHA512, примитивы libsodium (pysodium). Вход — `тип ‖ 0x00 ‖ нормализованное значение`. Реализация проверена тестовыми векторами RFC 9497.
3. **Ключ на тип и версию:** `DeriveKeyPair(seed, info = "anora-nazar:<тип>:<версия>")`; seed — секрет оператора из окружения. Ротация — новая версия: токены старой и новой версии не совпадают, кредиторы токенизируют заново. В целевом состоянии ключ делится между оператором и ЦБ (пороговый OPRF), в демо он один.
4. **Токен** — первые 32 байта выхода Finalize в hex. Ссылка на токен: `{kind, key_version, token}`.
5. **Кеш токенов** у кредитора допустим: значение и так его.

## События активности

Идут всегда, пока сеть включена у кредитора, до любой проверки — по ним сеть считает совпадения (Блок 2, шаг 4).

| Тип | Когда | Токены |
| --- | --- | --- |
| `application` | заявка или её новая версия оценена | ПИНФЛ (subject), телефон, устройство; ИНН поставщика у программной |
| `issuance` | кредит выдан | ПИНФЛ, ИНН поставщика у программной |
| `transfer` | первый перевод кредитных денег | ПИНФЛ, карта-получатель, доля кредита |
| `correction` | исправление события `refers_to` | полный новый набор токенов |
| `retraction` | ошибочная запись `refers_to` | — |

- **Дубли.** `event_id` уникален в паре «кредитор + контур». Повтор с тем же содержимым — `duplicates`, с другим — `conflicts`, событие не меняется. Новая версия заявки у кредитора — `correction` первого события заявки, а не новое событие: человек и заявка те же.
- **Отмены и исправления.** `correction` и `retraction` действуют с момента получения оператором: счётчик на момент раньше исправления считается по исходному событию (point-in-time). Отказ и отмена заявки клиентом — не `retraction`: заявка была подана, для серии по ПИНФЛ это и есть сигнал.
- **Время.** Оператор хранит `occurred_at` и `received_at`. `received_at` — время получения оператором; при прогоне истории (право `history`) — время из события.

## Счётчики

Ответ — только числа и совпадения с закрытыми делами, без имён других кредиторов (Блок 2, шаг 6).

- **Чужие события.** В счётчики не входят события самого запрашивающего кредитора: свои заявки он видит в своём индексе связей, двойного счёта нет. Так абляция «+ сеть» показывает ровно то, чего банк не видит сам.
- **Уникальные люди** — число разных токенов ПИНФЛ (subject), не событий; токен ПИНФЛ самого заявителя не считается. Повторные события и версии одной заявки число людей не меняют.
- **Point-in-time.** Учитываются события с `received_at ≤ as_of`, без `retraction` и с последней `correction`, полученными до `as_of`. `as_of` в запросе — только с правом `history` (обучение и проверка point-in-time); иначе — сейчас.

| Счётчик | Что считает |
| --- | --- |
| `pinfl_lenders_1h`, `pinfl_lenders_7d` | разные другие кредиторы с заявкой этого ПИНФЛ за окно (Блок 3: серия по ПИНФЛ, 1 ч и 7 дней) |
| `phone_people_24h`, `phone_people_30d` | разные другие люди с этим телефоном в заявках других кредиторов |
| `device_people_30d` | то же для устройства |
| `card_borrowers_30d`, `card_lenders_30d` | заёмщики и кредиторы с переводами кредитных денег на эту карту |
| `supplier_borrowers_30d`, `supplier_lenders_30d` | заёмщики и кредиторы программных заявок с этим поставщиком |

**Совпадения с закрытыми делами** (`confirmed`) — тип токена, типология и степень подтверждения, если токен запроса есть в результате проверки другого кредитора, подтверждённом до `as_of`.

## Результаты проверок

Отдельный поток, только закрытые дела (Блок 4): «подтверждённый фрод» — идентификаторы мошенника; «подтверждённое воздействие» — только идентификаторы мошенника (карта-получатель), не жертвы. Обоснованное подозрение, «не удалось проверить» и ложное срабатывание в сеть не уходят.

## Уведомления о новых совпадениях

Запрос счётчиков с `watch_until` подписывает `ref` на токены запроса. Когда другой кредитор присылает событие с тем же токеном, оператор отправляет кредитору `MatchNotification` (outbox, доставка по HTTP с повтором). Узел ставит заявке пометку «нужна новая оценка» — главный сценарий через сеть: зелёная заявка, связанная заявка в другом банке, отказ АБС до новой оценки. Подписка снимается по сроку.

## Защита от злоупотреблений

- **Квота OPRF:** вычислений за скользящее окно не больше `запас + коэффициент × число заявок кредитора за окно`. Перебор номеров через оператора упирается в число реальных заявок. Право `history` (прогон синтетической истории) квотой не ограничено.
- **Журнал запросов** у оператора: кто, когда, сколько токенов и какие счётчики спрашивал, без значений.
- **Контуры.** Песочница видит общий мир и свои события, чужих песочниц — нет. Сброс песочницы удаляет её данные у оператора.

## Сбой сети

Узел полностью работает без сети (Блок 3, «Сеть не ответила»): решение по внутренним признакам с причиной «сеть недоступна», признаки сети — пропуски, модели с признаками сети не запускаются, работают локальные. Перед Т2 узел повторяет запрос, если сеть снова отвечает.

## Отложено

- Пороговый OPRF с двумя держателями ключа — целевая архитектура (ревью ядра).
- Справочник цен из гистограмм — отложен в И4 по плану итераций; цены сравниваются по своим договорам.
