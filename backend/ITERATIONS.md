# Итерации бэкенда

Четыре итерации. Переход к следующей — когда выполнено всё из «Готово, когда» и зелёные `ruff`, `mypy`, `pytest`. Решения по ревью ядра (`docs/Решения по ревью ядра.md`) учтены ниже. Объём каждой итерации не урезается без согласования с владельцем. Сеть — последней, режим «без модели» — первым (CLAUDE.md, «Ядро: технические правила»).

## И1 · Путь денег без модели — готово

Заявка проходит путь «оценка → разрешение на операцию → итог» по настоящему HTTP между `bank-sim` и `node`. Живой отзыв работает на правилах и индексе связей. Журнал проверяем.

| Где | Что |
| --- | --- |
| основа | `pyproject.toml` (uv), compose для разработки (`postgres`, `node`, `bank-sim`, `anchor`), база и миграции каждого сервиса, настройки из окружения, ошибки, журналы, здоровье |
| `shared` | конверт события, идемпотентность (ключ, хеш параметров, ответ; другие параметры — 409), канонический JSON по RFC 8785, подпись Ed25519 ключом из файла, дерево Меркла, HTTP-клиент между сервисами |
| `node/realms` | общий мир и песочница посетителя; видимость «мир + свои записи»; сброс — удаление контура |
| `node/identity` | сиды ролей и сотрудников, демо-вход, API-ключи систем банка с правами |
| `node/applications` | снимки версий с хешем, отмены, пропуск версии держит заявку, пометка «нужна новая оценка» |
| `node/ingest` | идемпотентный потребитель, порядок версий, пометки в той же транзакции по индексу связей с блокировкой по возрастанию id, метрики задержки и «сигнал после резерва» |
| `node/index` | таблица появлений с `occurred_at` и `received_at`, счётчики на `as_of`, редкость атрибута, групповой флаг: две и более независимые редкие связи или всплеск |
| `node/policy` | YAML правил и порогов с версией и пунктом нормы, каталог кодов причин из Блоков 2–3, уровень — максимум из четырёх источников |
| `node/decisions` | Т1 и Т4 в режиме «без модели», чистая `decide()`, неизменяемая запись решения, воспроизведение |
| `node/permits` | Т2 и Т5: проверка и резерв одной транзакцией, удержания, итог, частичный уникальный индекс, просроченный резерв → «неизвестно» → сверка с АБС |
| `node/audit`, `anchor` | цепочка на контур, один писатель под advisory lock, контрольная точка → `anchor`, проверка с первой изменённой записью |
| `node/outbox` | исходящие события в той же транзакции и доставка |
| `bank-sim` | песочница посетителя, конвейер с обязательными шагами № 3759 и вызовом Т1/Т4, АБС (запрос разрешения, проводка, итог, статус по ключу операции), второй филиал, события источников, четыре кнопки сбоев |

**Готово, когда:**

- Главный сценарий проходит через API: зелёная заявка → связанная заявка во втором филиале → «нужна новая оценка» → АБС получает отказ с причиной. Контрольная ветка: нормальное связанное событие уровень не меняет.
- Кнопки «потерять итог», «повторить с другой суммой», «узел недоступен», «очередь отстаёт» ведут себя как в Блоке 1.
- Тесты: гонка резерва и пометки, повтор с теми же и с другими параметрами, уникальность операции, просрочка резерва и сверка, порядок и пропуск версий, воспроизведение решения, подделка журнала находится на первой изменённой записи, изоляция песочниц.
- Всё поднимается одной командой compose.

## И2 · Синтетический мир, признаки, модели — готово

Модели F1, F2, F3 обучены на синтетике и участвуют в решении. Абляция показывает вклад графа.

| Где | Что |
| --- | --- |
| `world` | население и семьи, организации, три кредитора, 8–12 месяцев событий, честное поведение, типологии F1–F3 с шумом и маскировкой (в F2 — и группы координации без общих идентификаторов), ловушки, поздние жалобы и исправления, задержанные исходы; параметры — YAML, согласованные с владельцем |
| `bank-sim` | прогон истории через интерфейсы узла строит общий мир; персонал — из мира; АБС держит контракт единственной проводки (уникальная бизнес-операция, повтор с тем же ключом) |
| `node/features` | паспорта признаков; каталоги зон 1–3 на `as_of`; цена против рынка по договорам своего банка (медиана и MAD, расширение группы); правдоподобие дохода (скачок, CUSUM, доля добровольных взносов); концентрации — сглаженная доля (m-оценка); признаки групп; семантика «нет данных» |
| `node/index` | две стратегии групп в одном формате: идентичность (связные компоненты по редким связям, локальный поиск от заявки) и координация (концентрация ролей во времени); спецификация `SPEC.md` и эталонные графы |
| `node/scoring` | реестр с контрактами; обучение F1 в Т1, F2 в Т1 и Т4 (признак канала, калибровка по каналу; общая или раздельные — по отчёту), F3 в Т4; разбиение по времени и по группам; калибровка; вклад признаков → причины; выпуск: теневой режим, сравнение, второй подписант |
| `node/quality` | PR-AUC, recall при доле ручной проверки и при 5 % FPR, Брайер, predictive equality, абляция «правила и граф без ML → поштучно → + граф», общая F2 против раздельных по каналам, худшие дни по нагрузке; внешняя проверка на BAF (скрипт загрузки, данных в репо нет) |
| `node/decisions` | источник «модель»: жёлтый по калиброванной вероятности, красный — оценочная стоимость риска (вероятность × сумма × доля невозвратной потери) выше аппетита; сравнение версий политики и модели на сохранённых входах |

**Готово, когда:**

- Модели обучены на общем мире и подключены к решению; модель с чужим контрактом не запускается, причина «без модели».
- Эталонные графы проходят, включая группу координации без общих идентификаторов.
- Воспроизведение даёт тот же уровень и те же причины.
- Отчёт качества и абляция считаются из данных; модели сравнены с базовым уровнем «правила и граф без ML».
- Тесты point-in-time: поздний факт не попадает в прошлую оценку; генератор действительно выдаёт поздние факты.

## И3 · Люди в контуре: проверки, дела, метки — готово

Три зоны проходят до исхода дела. Исходы становятся действиями и метками.

| Где | Что |
| --- | --- |
| `node/verification` | проверка намерения, сигнал «Меня просят взять кредит», пауза со сроком и эскалацией, скрипт звонка |
| `node/cases` | дело на заявку или группу, очереди по зоне, пакет улик, безобидные объяснения (родство, зарплатный проект, программная партия), чек-листы зон, решения по участникам, пять исходов и разрешённые ими действия, стоп-лист, ограничения ролей |
| `node/labels` | метки с происхождением; петля «исход → метка → обучение → тень → второй подписант» |
| `node/recalc` | Т6: пересчёт после пометки, ретро-поиск по выданным за 12 месяцев |
| `node/permits` | Т5 — акт, реквизиты, дела и реестр поставщика |
| `node/decisions` | Т3 — рекомендация транзакционному антифроду банка: контекст «кредитные деньги», графовый риск, правила получателя; решение за антифродом банка, без узла он решает сам |
| `node/policy` | смена порогов со вторым подписантом; журнал просмотра полных персональных данных |
| `node/texts` | утверждённые шаблоны для клиента и формулировки причин |
| `bank-sim` | приложение заёмщика, переводы с транзакционным антифродом (Т3), акты приёмки (Т5), жалобы и документы органов, сценарии трёх зон в один клик и свой ввод |

**Готово, когда:**

- Сценарии трёх зон доходят до исхода дела.
- Удержания ставятся и снимаются по исходу; метки уходят в обучение только из разрешённых исходов.
- Права ролей и ограничения («не своё подразделение», второй подписант — другой сотрудник) проверены тестами.

Сделано сверх списка и по ходу: проверенная связь (отпуск участника или «ложное срабатывание») не ставит повторное удержание той же версии заявки; пороги и выпуски моделей, утверждённые в песочнице, действуют только в ней; обзор риск-менеджера (доли уровней, очереди, дрейф PSI); каталог текстов для сотрудников и заёмщиков (`GET /v1/texts`).

## И4 · Сеть кредиторов и готовность стенда — готово

Сеть добавляет сигналы, которых не видит один банк. Бэкенд готов к публичному стенду.

| Где | Что |
| --- | --- |
| `network-operator` | OPRF на ristretto255 (pysodium), отдельный ключ на тип идентификатора (пороговый OPRF — целевая архитектура), события активности и счётчики без событий самого запрашивающего банка, результаты проверок из закрытых дел, квоты запросов, журнал запросов; справочник цен из гистограмм отложен |
| `node/consortium` | адаптер, выключен по умолчанию; переключатель; признаки сети в моделях; причина «сеть недоступна» |
| `bank-sim/lenders` | кредиторы Б и В — генераторы событий с тем же клиентом OPRF |
| `node/quality` | абляция «+ сеть» |
| стенд | compose для сервера, лимиты ресурсов, срок жизни песочниц, нагрузочный прогон с одновременными посетителями |

**Готово, когда:**

- Главный сценарий работает через сеть; переключатель сети меняет его исход.
- Абляция «поштучно → + граф → + сеть» считается из данных.
- Нагрузочный прогон с одновременными посетителями проходит без ошибок и без влияния песочниц друг на друга.
- Стенд поднимается на сервере.

Сделано по ходу. Сетевой контракт `network-contract-1` описан в `network_operator/SPEC.md`: токены, уникальные люди, дубли, исправления и отмены, point-in-time.

- **OPRF** — RFC 9497 на libsodium, проверен официальными векторами.
- **Включение сети** — предложение порога `network.enabled` со вторым подписантом в политике v4.
- **Уведомления оператора** о новом совпадении у другого кредитора ставят «нужна новая оценка» — главный сценарий через сеть.
- **Модели** — локальная и «-net» на одних окнах.
- **Т3:** дробление переводов считается вместе; карта-получатель проверяется по сети.
- **Проверка намерения** не снимает независимые основания.
- **Мир** `world-v2`: межбанковские схемы и честные ловушки.
- **Стенд:** `deploy/stand` — шлюз, лимиты, отдельный процесс обучения, версия сборки.
- **Демо-вход** — только при `NODE_DEMO_MODE` и только в песочницу.
- **Нагрузка:** 30 посетителей без 5xx и без утечек между песочницами; решение по зелёной заявке — p95 0,6 с.
- **Стенд:** https://nazar.clusteros.co.uz — мир и модели посчитаны локально и перенесены копиями баз (`deploy/stand/transfer.sh`); сквозные тесты проходят через HTTPS.

**Абляция на world-v2** (PR-AUC при тех же окнах и доле проверки; поштучно → + граф → + сеть):

| Модель | Поштучно | + граф | + сеть |
| --- | --- | --- | --- |
| F1 | 0,34 | 0,30 | 0,34 |
| F2 онлайн | 0,89 | 0,85 | 0,85 |
| F2 программы | 0,45 | 0,24 | 0,21 |
| F3 | 0,46 | 0,47 | 0,45 |

На всём потоке сеть почти ничего не добавляет: межбанковских схем у банка A единицы на окно проверки. Механизм виден на уровне сигналов: серию по ПИНФЛ за час с одним чужим кредитором дают 8 из 58 позитивов F1 и 0,23 % честных заявок. Правило политики v4 требует двух чужих кредиторов, порог — на решение владельца.
