# Итерации фронтенда

Три итерации. Фронт идёт вслед за бэком (`backend/ITERATIONS.md`): экран собирается, когда у него есть API. Моков на фронте нет — пока API экрана нет, экран не начинаем, а контракт, который ему нужен, отдаём бэку (раздел «Что нужно от бэка»). Переход к следующей итерации — когда выполнено всё из «Готово, когда» и зелёные `eslint`, `tsc --noEmit`, сборка.

Решения владельца по виду (11.10.2026):

- шрифт — Wix Madefor (Text для интерфейса, Display для крупных заголовков), файлы в сборке через `@fontsource`, без запросов к сторонним CDN;
- акцент основной кнопки — токен `--color-accent`, по умолчанию чёрный; акцент банка меняется одной строкой;
- всё на русском, словарь готов к узбекскому;
- знак продукта — слово «Anora Nazar» жирным, «Anora» красным, без иконки.

Референсы (Блок 5 и картинки владельца): тон UXDA «Simply Quiet» и «Calm Hideaway» — белый фон, тонкие линии вместо теней, неподвижные боковые панели, меняется только центр, акцент только на главной кнопке; плотные таблицы Carbon (строка 32–40 px); очередь → карточка → исход как в Stripe Radar с J/K; лента действий MOJ Timeline; прерывание MOJ Interruption card; предупреждение GOV.UK Warning text.

## Ф1 · Основа, вход и путь денег — сделано, кроме выкладки

API готов (бэк И1–И2). Проверяющий открывает стенд, выбирает роль, подаёт заявку своим вводом, видит решение с причинами, исполняет его в АБС с кнопками сбоев и проверяет журнал.

| Где | Что |
| --- | --- |
| основа | Vite, React, TypeScript strict, React Router, TanStack Query, ESLint, Prettier; сервис `web` в compose: в разработке — Vite с прокси, на стенде — nginx со статикой и прокси; один адрес для всех сервисов: `/api/node`, `/api/bank` |
| `shared/api` | типы из OpenAPI `node` и `bank-sim` (openapi-typescript, файлы в репо, команда генерации), клиент: песочница, токен сотрудника, ключ идемпотентности, типизированные ошибки с текстом для человека |
| `shared/styles` | токены: цвета iOS из `CLAUDE.md`, акцент, отступы, радиусы, брейкпоинты, высоты строк, длительности; шрифт; базовые стили; `prefers-reduced-motion` |
| `shared/ui` | кнопка, поле, выбор, карточка, бейдж, таблица (на телефоне — список карточек), заглушка строк, пустое состояние, ошибка, модальное окно, нижняя шторка, вкладки, выпадающее меню, сводка «ключ — значение» (GOV.UK Summary list) |
| `shared/lib` | суммы табличными цифрами «30 000 000 сум», дата ДД.ММ.ГГГГ и время 24 ч по Ташкенту |
| сессия | начать демо (песочница в `bank-sim`, контур в узле), вход сотрудника без пароля, переключатель ролей в шапке по группам «Банк (имитатор)» и «Anora Nazar», сброс демо |
| `/` | вход: о проекте в трёх абзацах, роли с описанием из сидов, начать демо |
| `/bank/conveyor` | новая заявка своим вводом: канал, заявитель, условия, итоги обязательных проверок; ответ узла — уровень, причины, удержания; изменение условий → новая версия |
| `/bank/core-banking` | операции по ключу бизнес-операции: запрос разрешения, проводка, итог; кнопки сбоев с пометкой «симулятор» |
| `/decisions/:decisionId` | уровень, причины с источником и пунктом нормы, доказательства, версии политики, моделей и признаков, повтор решения и сравнение версий |
| `/risk/audit` | журнал своего контура, проверка целостности против якоря, первая изменённая запись |

**Готово, когда:**

- Стенд поднимается `docker compose up --build -d`, фронт открывается на одном адресе с API.
- Путь «заявка → решение → разрешение → итог» проходится руками с ноутбука и с телефона; сбой узла и повтор с другой суммой показаны понятной ошибкой, а не пустым экраном.
- Два посетителя в разных браузерах не видят записей друг друга; сброс демо возвращает исходное состояние.
- Экраны проверены на 390 и 1440 px.

Статус на 11.10.2026: путь «вход → заявка → решение → АБС → журнал → повтор решения» пройден в браузере на 1440 и 390 px; `web-check` зелёный. Не сделано: прогон с реального телефона (нужен стенд по HTTPS, Ф3) и два посетителя в разных браузерах. Тексты причин — пока коды: ждут `node/texts`.

## Ф2 · Рабочие места сотрудников — сделано

Ждёт бэк И3 (`node/cases`, `node/verification`, `node/texts`, смена порога) и отчёты И2.

| Где | Что |
| --- | --- |
| `/analyst` | три неподвижные колонки: очередь по оценочной стоимости риска, заявка, действие; J/K по очереди; на телефоне — очередь, затем карточка |
| `/analyst/cases/:caseId` | сначала уровень и 3–5 причин словами с меткой источника (банк, клиент, сеть) и доказательствами, затем события сессии; балла нет; справа — звонок по номеру из госреестра, вопросы кнопками, исход из пяти, заметка, лента «кто, когда, что» |
| `/control` | список дел групп и программ (MOJ Case list): стратегия группы, заявки, удержания, срок |
| `/control/cases/:caseId` | граф дела (Cytoscape) с фильтром типов связей, легендой и подсветкой; улики (порог правила рядом с фактом); безобидные объяснения; решение по каждой заявке, затем исход дела; ретро-поиск; что дело уже сделало с деньгами (отказ на Т5) |
| `/risk` | доли уровней, очередь, дрейф |
| `/risk/models` | качество на отложенной выборке с пометкой «синтетика» или «BAF», абляция, общая F2 против раздельных, справедливость, худшие дни, версии, выпуск со вторым подписантом |
| `/risk/policy` | пороги и версии; предложение и подтверждение другим сотрудником |
| виджеты | лента действий, список причин, панель улик, путь разрешения |

Статус на 11.10.2026: все экраны Ф2 собраны на API И3 и пройдены в браузере на живом стенде — очередь и дело аналитика до исхода (J/K, звонок кнопками, чек-лист, лента с номерами журнала), дела внутреннего контроля с графом Cytoscape и решением по каждой заявке, обзор риска (visx), пороги со вторым подписантом, качество моделей в новом формате отчёта (скользящая проверка, интервалы, кандидаты, point-in-time), выпуски и обучение. Тексты причин, признаков, уровней, исходов — из `node/texts`.

**Готово, когда:**

- Аналитик проходит красную заявку от очереди до исхода с клавиатуры; исход и автор сразу видны в ленте и в журнале.
- Внутренний контроль решает по каждой заявке группы; групповой флаг не предлагается как основание отказа.
- Порог не подтверждается тем, кто его предложил: ошибка понятна.
- Тексты причин приходят с бэка; на фронте нет ни одного кода причины в виде текста.

## Ф3 · Заёмщик, сценарии, сеть, стенд — сделано, кроме выкладки

Ждёт бэк И3 (`bank-sim/borrower_app`, `bank-sim/scenarios`) и И4 (сеть).

| Где | Что |
| --- | --- |
| `/borrower` | приложение банка: на широком экране — в рамке телефона, на телефоне — без рамки; зелёный — только шаги банка; жёлтый — два вопроса кнопками, «Продолжить», «Отложить», «Меня просят взять кредит» (сигнал молча); красный — пауза с одной кнопкой «Понятно» и «Позвонить в банк», без «продолжить»; статус «на проверке, банк позвонит» |
| `/bank/conveyor` | сценарии трёх зон в один клик рядом со своим вводом |
| `/risk/network` | сеть вкл/выкл, счётчики, абляция «+ сеть» |
| стенд | сборка nginx, HTTPS на сервере, прогон сценариев с телефона и ноутбука, доступность с клавиатуры, контраст AA, увеличение шрифта без поломки |

Статус на 11.10.2026: приложение заёмщика (персоны, заявка, экраны по `screen`, вопросы, «Меня просят», пауза без «продолжить»), сценарии в один клик в конвейере, перевод Т3 и акт приёмки Т5 в АБС — сделаны и проверены в браузере. Сеть (И4): `/risk/network` — состояние, вкл/выкл со вторым подписантом, правила, ответы сети в решениях, счётчики оператора; переключатели в порогах политики; кнопка сбоя «сеть недоступна» в АБС; сценарии сети проверены (жёлтый при включённой сети). Абляция «+ сеть» — на `/risk/models`. Осталось: выкладка по HTTPS (`deploy/stand`).

**Готово, когда:**

- Три сценария запускаются в один клик и доходят до экрана заёмщика и до карточки сотрудника.
- Переключатель сети меняет исход главного сценария на глазах.
- Стенд открыт по HTTPS; прогон с телефона и ноутбука без ошибок.

### Контракты под экраны Ф2–Ф3 (предложение фронта)

Пути и поля — предложение. Окончательную форму задаёт бэк, фронт берёт типы из OpenAPI. Всё — в контуре посетителя и по правам роли. Общее правило: ответы — Pydantic-модели, без `dict[str, Any]`, иначе типов на фронте нет.

**Тексты (`node/texts`)** — `GET /v1/texts?audience=staff|client`, с версией каталога:

- причины: код → заголовок и пояснение для сотрудника, шаблон для клиента без названия признака;
- признаки: код → название (для вклада признаков у риск-менеджера);
- уровни, источники (банк, клиент, сеть), действия, исходы дела, статусы удержаний.

**Аналитик (`node/cases`, `node/verification`):**

- `GET /v1/cases?queue=online` — очередь по оценочной стоимости риска: дело, заявка, сумма, канал, точка, уровень, оценочная стоимость с пометкой «оценочно», срок, кто взял;
- `GET /v1/cases/{id}` — заявка: продукт, сумма, срок, стаж клиента, прежние кредиты; 3–5 причин с источником и доказательствами; события сессии со временем; ответы сети; скрипт звонка (источник номера — госреестр, вопросы с вариантами ответов кнопками); допустимые исходы; лента «кто, когда, что, почему»;
- `POST /v1/cases/{id}/assignment` — взять в работу;
- `POST /v1/cases/{id}/outcome` — ответы звонка, исход, заметка; одна запись видна и в ленте, и в журнале.

**Внутренний контроль:**

- `GET /v1/cases?queue=group` — стратегия группы (идентичность или координация), заявки, удержания, срок;
- `GET /v1/cases/{id}/graph` — узлы с типом (заявка, человек, телефон, устройство, адрес, работодатель, поставщик, помощник, сотрудник, карта) и уровнем; рёбра с типом связи (рекомендация, договор и оплата, общий идентификатор) и признаком «редкая»;
- улики: порог правила рядом с фактическим значением; безобидные объяснения; что дело сделало с деньгами (отказ на Т5);
- `POST /v1/cases/{id}/applications/{application_id}/decision` — удержание, отпуск или отказ по одной заявке с основанием; роли участников; исход дела; ретро-поиск Т6.

**Риск-менеджер:**

- `GET /v1/risk/overview` — доли уровней по дням, размер очередей, дрейф признаков;
- `GET /v1/models/releases` — выпуски, ждущие второго подписанта (без него подтверждать нечего);
- отчёт качества: доля ручной проверки и FPR, при которых считался recall; источник данных («синтетика» или «BAF»);
- `GET /v1/policy/versions`, `POST /v1/policy/proposals`, `POST /v1/policy/proposals/{id}/approval` — пороги со вторым подписантом.

**Заёмщик и сценарии (`bank-sim`):**

- персоны из синтетического мира; заявка из приложения; вопросы проверки намерения и тексты экранов по коду из `node/texts`; сигнал «Меня просят взять кредит»; статус паузы;
- `GET /v1/scenarios`, `POST /v1/scenarios/{code}/runs` — сценарии трёх зон в один клик.
